# 08 · Darwin arm64 and arm64e machine ABI

This is a source audit of dev b404252 plus the runtime-hop work in progress. No fixtures were built or run for this report. “Source-risk” marks a specification/consumer discrepancy that still needs a witness through a real analysis entry point. The positive and negative oracles below are proposed cases. See scope-and-evidence.md for separately measured results. Use the exact Swift 6.4.2 compiler on PATH. The xcrun Swift 6.4.0 driver is a separate compatibility run.

LLVM/Clang references use fb5f84d903a3b4e7aea15cd5666598a46f56c833. Swift references use 83eb12448e4323abbf81b0153dced2faff02d22f. Consumer line numbers reflect the audited tree.

## Findings

### M01 · Baseline call effects and register conventions — partial

- The Darwin default has callee-saved x19–x29 and d8–d15. The function preserves its *incoming* return address according to its own exit contract, while BL changes the caller’s x30. x16/x17 can be used by linkage islands. Darwin reserves x18. SwiftError and SwiftTail select different masks. Vector PCS, SVE PCS, TLS, PreserveMost, PreserveAll and PreserveNone also select separate masks. [Darwin masks](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64CallingConvention.td#L728) [Mask selection](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64RegisterInfo.cpp#L259) [x18 reservation](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64Subtarget.cpp#L381)
- ValueTracking.swift:2183–2213,2353–2354 invalidates caller-saved data and NZCV, including x18 and x30. x18 invalidation safely declines value continuity. CalleeRegisterSummary.swift:439,648 separately tracks entry argument writes; :1531,2044–2105 track preservation. FlagsAcrossCallTests and NativeVectorPreservationTests exercise existing pieces. No shared selector combines caller/site convention with local body exceptions and proof width. Applying default callee-saves to proven PreserveNone or arbitrary outlined code would retain stale data. Discarding extra saves for a known stronger mask loses precision.
- Implement a per-edge contract with separate read/define/preserve masks by register slice, SP effect, memory effect, return mode and provenance. Keep x18 outside normal parameter/result banks and track NZCV invalidation independently. For unknown foreign convention use an explicit unsupported edge where the ordinary ABI cannot be established. Oracle: pinned llc caller/callee pairs for standard, preserve_none, preserve_most, vector PCS and Swift attributes, plus arm64 assembly that samples x19, NZCV, LR and d8/q8 around calls. Change only the convention or written slice and require the corresponding inferred facts to change in both renderers and summaries.

### M02 · Swift hidden-register inputs and defs — source-risk

- Darwin TableGen gives x8 to sret, x15 to nest, x20 to swiftself, x21 to swifterror, x22 to swiftasync, and x23 to swiftcoro. These flags have independent meanings. SwiftTail removes x20/x22 from the baseline saved set, and SwiftError removes x21. Check actual call-site regmask and explicit operands together. [Parameter flags](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64CallingConvention.td#L363) [Formal attribute lowering](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64ISelLowering.cpp#L7909)
- CalleeRegisterSummary.swift:598–613 and :2044–2112 use an opaque ABI input set that ends with x20/x21. The accompanying x22 exclusion describes ordinary calls. That set is insufficient as a common fallback for a real swiftasync/swiftcoro entry and cannot establish absence of an alias passed in either role. ValueTracking.swift:2085–2115 has separate body-based x22 reachability. :2215 onward handles the error convention separately. Reports 01/03/04 own semantic role recovery.
- Feed proven entry and edge attributes to M01. Keep address reachability separate from register preservation and classify register uses as parameters, in/out state, or machine-only state. Oracle: isolated IR variants changing just swiftasync/swiftcoro/swifterror/swiftself and native sentinel calls using each special register. Mutate x22/x23 capture and replace known local target with unresolved indirect target. Require a lost proof where evidence disappears and exact preservation where a body demonstrates it.

### M03 · SIMD preservation and representation slices — partial

- Default d8–d15 preserved widths are 64 bits, while q values have 128 bits and vector PCS has a different preserve set. In argument placement H/S/D/Q and scalable Z/P classes must remain distinct. [Bank assignments](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64CallingConvention.td#L390) [Darwin CSR](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64CallingConvention.td#L730)
- ValueTracking.swift:5150–5168 limits preserved scalar values by width. CalleeRegisterSummary.swift:619–648 records argument width and handles lane writes separately from full writes, while Preservation.writtenRegisterKeys at :1536 works by vector key. Exact low-word preservation can decline when a write is confined to the upper lane. A scalar width alone cannot assert a complete Q value or prove simultaneous lane origins. Existing NativeVectorPreservationTests, FloatBitPatternTests and CalleeBodyTransferTests cover slices.
- Use bit intervals for transport, with architectural zeroing on scalar destinations represented separately from lane inserts, and carry memory byte intervals across spills. Test low lane unchanged/high lane changed, q/d/s/h stores and reloads, widening after call, unknown indexed lane, unmodeled scalable operations, and selection of vector PCS. Oracle: assemble and compare both 64-bit halves; mutate only lane index or copy width. No reconstructed upper-half fact may survive with only d preservation.

### M04 · Stack parameter packing and tail stack ownership — partial

- Darwin assigns fixed i8/i16/i32 actual stack slots of 1/2/4 bytes, normal scalar 8, Q 16. i128 spills as a pair with 16-byte stack alignment and cannot start in x7. ByVal and consecutive-register groups have their own allocation rules. Darwin variadics put unnamed args on the stack with distinct promotion/slot rules. ISel tracks bytes in the incoming area and can reuse or pop argument space on tail calling conventions. [Darwin PCS and varargs](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64CallingConvention.td#L358) [Incoming stack bookkeeping](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64ISelLowering.cpp#L8211) [Tail stack checks](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64ISelLowering.cpp#L8703)
- ValueTracking.swift:2106–2115 scans at most 16 contiguous 8-byte outgoing slots for escaping values and :2432 snapshots stack state. CalleeRegisterSummary.swift:871–929 has an incoming-stack predicate, not a byte placement description. A hole or packed mixed-width argument before a pointer therefore needs explicit scrutiny for the alias proof as well as rendering. Report 01 owns Swift placement and 06 owns foreign variadics.
- Feed typed byte/align ranges into stack snapshots and escape checks, use conservative ranges when placement is unresolved, and distinguish entry-SP, current-SP and tail destination coordinates. Oracle: Clang and Swift spills at each bank boundary, >16 stack words, packed UInt8/UInt16 followed by pointer, i128 at x7 boundary, HFA register exhaustion and a variadic counterpart. Verify native pointee mutation and paired caller/callee bytes. Mutate only the offset or tail adjustment and require forwarding or memory precision to drop.

### M05 · Frame ownership, red zone, outlined helpers and stack probes — partial

- LLVM's red-zone eligibility checks leaf/call, FP and allocation size. Darwin target red-zone size is 128 in the target lowering helper. Frame lowering handles Swift async extended frame records, alignment, FP and partial SwiftCoro returns. The machine outliner can save LR in a register or on the stack and arrange stack fixups/authentication. [Red-zone eligibility](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64FrameLowering.cpp#L503) [Target red zone](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64ISelLowering.h#L491) [Extended frames](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64FrameLowering.cpp#L2035) [Outliner](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64InstrInfo.cpp#L10297)
- ValueTracking.swift:1676 recognizes frame layout and :1990 handles special probing. CalleeRegisterSummary.swift:474 identifies probe instruction patterns, :962 recognizes one exact framed wrapper, :1584 traces LR exits, :2044 models SP-relative probe writes and unknown-call effects. CalleeRegisterSummaryTests:208,356,766,781,844 cover dynamic/SP ownership/probing. Existing tests establish specific instruction regions, not a frame family contract. An outlined helper can have machine inputs outside standard slots; a function-symbol boundary alone cannot prove conventional preservation.
- Keep geometric SP bounds, alignment and call-time below-SP ownership separate from saved-register slots and body reloads. Share one exact probe contract across both engines after pinning its provider/disassembly; reconcile different current invalidate lists by checking actual instructions and linkage. Use unwind data as corroborating frame evidence when present. Oracle: pinned compiler with/without red-zone use, VLA/large frame, frame-pointer omission, outliner under -Oz and hand-written alternate LR register; compare native register snapshots and SP, emitted assembly and unwind. Mutate LR restore, stack writeback, SP bound and branch to incomplete helper. Drop proofs independently on each mutation.

### M06 · Exit classification, tails and resumptions — partial

- ISel checks ABI compatibility before a sibling tail, including incoming-area reuse and mask compatibility. SwiftTail is a distinct convention. SwiftCoro partial return uses RET_POPLESS and frame lowering preserves coroutine state for later continuation. [Tail checks](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64ISelLowering.cpp#L8458) [Partial return lowering](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64FrameLowering.cpp#L2581)
- FunctionCFG.swift:85–152 provides control flow, not endpoint semantics. CalleeRegisterSummary.swift:951–990 models pure/framed forwarding and :1584–1602 verifies return-address origin. ConditionalTailEffectsTests and IntegerTailReturnProofTests cover distinct conditional states and integer result contracts. Reports 03/05 cover async and coroutine control transfers. Outside-body branch form and intact LR alone leave possible jump-table, fragment, noreturn, suspension, conditional and coroutine exits.
- Carry exit kind, target evidence, entry/exit SP relation, live incoming LR/authenticator and logical result contract separately. Only proved endpoint/result pairs become source returns. Oracle: assembly for true sibling tail, conditional tail plus ordinary fallthrough, noreturn tail, shared epilogue, async hop and SwiftCoro partial return. Flip single target provenance, SP balance or return-bank signature while preserving branch encoding family. Raw CFG remains usable while source return declines.

### M07 · Pointer-authenticated code, data and return address — source-risk

- Swift chooses different schemas for ordinary function pointers, class methods, protocol witnesses, value witnesses, context/descriptor pointers, async parent/resume, block invoke and each coroutine resume family. Storage address and declaration/type-derived discriminator may both matter. A return authenticator must match key and SP modifier established at signing. [Swift discriminator inventory](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/include/swift/ABI/MetadataValues.h#L1677) [Async context stores](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenCall.cpp#L3410) [Coroutine schemas](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenCall.cpp#L5050) [Method schemas](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenMeta.cpp#L327)
- RuntimeFunctionReference.swift:21–45 allows authenticated branch forms but returns only the slot. Its check establishes x16's loaded origin, without pairing branch key/modifier with chained bind authentication metadata. Disassembler.swift:5835–5864 separates rebases/binds and keeps exact import provenance but projects targets without key/discriminator in that path. CalleeRegisterSummary.swift:1592 explicitly accepts RETAA/RETAB as x30 returns. StructuredDecodeTests:203 checks branch classification and RuntimeFunctionReferenceTests:102 checks complete scratch-register import islands. Neither classification nor slot resolution establishes authentication compatibility.
- Add independent address identity, pointer category, fixup authentication tuple, storage provenance and signing/authentication transition evidence. For unresolved authenticated edges keep the structural candidate and restrict proved invocation/preservation to verified contracts. Derive schema from the specific descriptor field or typed endpoint. Handle sign, auth, strip, resign, authenticated load/branch and RETAA/B with a regression for key and modifier mismatches. Oracle: arm64e IR bundles and sign/auth intrinsics, assembler and fixup metadata for a real image, optionally run on a loader supporting the slice. Mutate only key, diversity, address diversity, storage slot or auth branch modifier. A slot symbol can stay known while the callable edge becomes unresolved.

### M08 · Symbol identity, aliases and dynamic target selection — partial

- A declaration, emitted entry, linker symbol, import slot and runtime provider are different proof objects. Back deployment can forward to either original or fallback after an availability guard. [Swift forward application](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/SILGen/SILGenAvailability.cpp#L326)
- RuntimeFunctionReference.swift:48–95 requires exact symbol/provider for runtime contracts and zero export modifiers for direct exports. Disassembler.swift:3089–3237 handles indirect symbols and imports, :5496–5605 resolves slots, :5739–5755 validates strong binds including legacy lazy setup and :5868 onward checks legacy opcodes. RuntimeFunctionReferenceTests:32–102 tests same spelling, provider mismatch and malformed islands. Reexports, symbol aliases, storage in auth/GOT slots, weak/coalesced choices, resolver/flat namespace and load-path aliases need explicit outcomes. A nonzero pointer addend supports address lookup only with its own validated typed use.
- Use one identity resolver across grouped/single-function APIs. Store both linker identity and feasible runtime endpoints with evidence for every hop. Require exact contract or a common contract proven for all feasible alternatives. Oracle: two dylibs and paired clients with aliases, reexports, strong/weak/flat, lazy/nonlazy/chained/authenticated slots, addends, local same spelling and availability selected fallback. Use Mach-O load commands/export trie and native endpoint sentinel (where runnable). Change one ordinal, export flag, target, entry addend or availability branch. No runtime-specific effect may survive an incompatible alternative.

### M09 · Integer, FP and vector operations at ABI boundaries — partial

- Width is part of Darwin slot placement and the i1/i8/i16 to i32 register location rules. Extension is selected from IR flags and actual lowering. A register key does not prove sign extension or pointer-width preservation. [Darwin width rules](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64CallingConvention.td#L404)
- InstructionSemantics.swift:13–22,55–187 models scalar integer operations and aliases with explicit sign/zero extension. ValueTracking.swift:4363–4421 distinguishes scalar FMOV from immediate vector/lane forms and :5139 onward handles vector bits on reads across calls. ABI-critical checks include W writes zeroing X upper half, bitfield insert preserving other bits, signed loads, endian byte packing, pair load/store and writeback, FP payload bitcasts versus conversions, and width of the last NZCV producer. FlagsAcrossCallTests, ABISourceLoweringTests:405 and FloatBitPatternTests:191 cover examples. Missing semantics must kill every affected width and flag fact instead of passing a pointer or scalar through.
- Gate result and argument transport on explicit bit-width/byte coverage. Keep numeric conversion and bit reinterpretation distinct. Oracle: hand assembly and native bit-pattern checks using signed and unsigned boundary values, NaN payloads, signed zero, H/S/D lane inserts and narrowed stores opposite wider loads. Mutate one W/X, pre/post-index, lane or conversion form. Compare machine facts before judging rendered source sugar.

### M10 · ABI version, target feature and deployment selection — unverified

- Swift exports a Swift ABI version to TBD. That version, compiler version, target slice, load-command minimum OS and available runtime implementation describe different axes. SILGen can choose a back-deployment thunk, and LLVM can make async FP layout deployment-conditioned. [Swift ABI version](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/IRGenModule.cpp#L2345) [TBD field](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/TBDGen.cpp#L636) [Thunk selection](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/SILGen/SILGenAvailability.cpp#L298) [Async frame selection](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64FrameLowering.cpp#L2039)
- Current provider checking in RuntimeFunctionReference.swift:66–95 proves a name/provider family, with no deployment argument there. ValueTracking.swift:1676 and CalleeRegisterSummary.swift:1531 contain local fixed machine assumptions. Introduce a shared target/deployment envelope using facts independently supported by the artifact. Treat missing ABI/compiler version as unknown.
- Oracle: one module at two deployment minima and one library evolution client retaining the availability branch, lower to SIL/IR, then compare load-command versions, generated frame metadata, endpoint code and runtime sentinels. Mutate only availability/proven provider and require affected contract to decline. Unsupported slices need an explicit boundary before applying LP64 rules.

- Inventory every SILFunctionTypeRepresentation in ExtInfo.h:338. Thick/Thin/Closure/Block/KeyPath getter,setter,equals,hash map to 05, Method/ObjCMethod/CFunctionPointer/CXXMethod to 06, WitnessMethod to 02. AST aliases LastAST and FirstSIL do not add cases. Ensure each has positive or explicit-decline coverage for value storage, entry, and application.
- Enumerate each ParameterConvention and ResultConvention from Types.h:4461 and :4918. Reports 01 and 05 cover physical/order and thunk relations, 06 adds CXX and foreign roles, 07 owns storage ownership. Generate independent rows for combinations that change shape or observable ownership, including tuple, indirect result, and aliasable/inout.
- Enumerate SILCoroutineKind from Types.h:5238 and map each non-None case to 03/05 plus M06 exit behavior. Enumerate every MetadataKind.def entry for 02/07 and tie each parser family to a positive or an explicit-decline row. Do not classify a metadata pointer as callable, or treat an unfamiliar tag as a known payload.
- Dynamic replacement and prior implementation belong in M08 and 06. IRGenSIL.cpp:1996 emits a prior-implementation thunk. GenDecl.cpp:1891–1931 models a chain link with distinct sync/async/coroutine pointer-auth schemas. Current SwiftRuntimeSignatures.swift:267,294 exposes scope functions but supplies no chain proof. Use pinned SIL/IR plus replacement and previous-implementation native sentinels. Change the installed link and ensure the declared call ABI stays while unsupported body-derived clobber and memory refinements expire. [Prior implementation thunk](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/IRGenSIL.cpp#L1996) [Chain entry](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenDecl.cpp#L1891)

Oracle: imported Objective-C declarations with different completion positions and error conventions, Swift import/export thunks, native success and error sentinels. Mutate only the slot or polarity and require synthetic async bridge claims to decline. [Imported completion](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/SILGen/SILGenApply.cpp#L6278) [Native-to-foreign thunk](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/SILGen/SILGenBridging.cpp#L1517)
- Implement M01/M02/M10 contract selection first, with M04 shared byte placement. Then M05/M06 edge and frame state, M07/M08 endpoint proof, and M03/M09 transport. Deploy stricter endpoint gating as soon as provenance fields exist. For each chunk inspect direct, grouped, standalone/shared-cache where relevant, and both renderers. Require at least one skip-free real target/consumer test for supported rows, a negative for unsupported rows and an isolated mutation that breaks each newly claimed inference. Compare pinned SIL/IR, target assembly/Mach-O and native sentinel observations independently where the target is executable. Fixture discovery skips are not evidence.
- Remaining outside this finite gate: arm64_32 and other platforms, custom LLVM preserve masks and scalable/streaming SVE/SME beyond explicit decline, private runtime SPI and future format tags, all dynamic-loader policies and in-process interposition, security enforcement or PAC validity at runtime, unwind/exception behavior outside the chosen Swift/foreign runtime boundary, and comprehensive ISA semantics or malformed binary recovery. A documented unknown is required before applying a rule based on any of these.
