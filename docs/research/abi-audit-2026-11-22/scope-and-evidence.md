# Swift ABI audit scope and evidence

Public reproducer sources and commands are in [probes](probes/README.md). The original compiled outputs remain under ignored `work/abi-gap-audit`. The frozen decompiler used for the spot checks has SHA-256 `aad2983cbd6d04dc9a3e5adf12d7e9c04c35b7ed2095385cc5e9fe14b0c339ce`; its code is the locally qualified witness slice.

The audit targets swiftdc's arm64 and arm64e Mach-O analysis. It covers Swift native conventions, the C and Objective-C interoperability needed by Swift, compiler-generated entry points, runtime contracts, metadata, and the machine-state rules those conventions require. An unsupported architecture is not an implicit extension of this scope.

Compiler source: swiftlang/swift release swift-6.4.2-RELEASE, commit `83eb12448e4323abbf81b0153dced2faff02d22f`, in `work/abi-gap-audit/swift-6.4.2`. LLVM and Clang release source is available at `fb5f84d903a3b4e7aea15cd5666598a46f56c833` in `work/abi-gap-audit/llvm-6.4.2`. These public release sources match the command-line Swift version, not the exact Apple internal build. `/Library/Developer/CommandLineTools/usr/bin/swiftc` is Apple Swift 6.4.2, swiftlang-6.4.2.1.9, clang-2100.4.1.1. `xcrun swiftc` selects Xcode's Swift 6.4.0, swiftlang-6.4.0.34.1, clang-2100.3.34.1. Both default to arm64-apple-macosx27.2.0, while the Xcode SDK is MacOSX27.0.sdk. The initial generic pack probe used Xcode 6.4.0 with explicit deployment target macOS 15. A separately named `GenericPackProbe.6.4.2.ll` was then emitted with the explicit command-line 6.4.2 executable. Every oracle must keep compiler, SDK, target, deployment target and feature modes attached to its results.

Swiftdc committed baseline is `b404252`, containing locally qualified witness code `e639a66cc91af43e131ec4bcbbe3e53c0f808e7c`. Uncommitted runtime identity, terminal endpoint and useInt acceptance tests are preserved as work in progress. No audit may treat these as published or qualified behavior.

Eight assignments: value lowering; generics and witnesses; async; errors and exits; closures and specialization; receivers and foreign dispatch; ownership and coroutines; machine ABI. Three subagents can run alongside the coordinator, so the assignments run in waves.

Each reported gap must name compiler evidence, current implementation and tests, an evidence status, an implementation dependency, an independent acceptance oracle, negative and mutation checks, and a closure criterion. Historical OPEN and FIXED labels are leads and must be reconciled against current code.

## Validation gaps to include in the combined plan

The existing `Tools/ghidra-compare/interface_oracle.py` checks sets of seeded entry registers. Its `lowered` parser excludes unplaceable aggregate/byval forms, more than eight registers in either bank, and variadics. `oracle_for` collapses cases that differ across optimization and resilience configurations to unchecked. It does not score x8, result values, ordered source-parameter identity, call sites, ownership, error paths, or async temporal transport. Compiler source rules need a normalized ordered ABI oracle covering those roles and explicit unchecked counts; a register-set match cannot establish whole ABI correctness.

The new baseline focus rebuilt successfully in 49.39 seconds. Twenty tests ran; the optimized useInt positive had six intended failed assertions, one for each of pseudo/structured across filtered/array/streaming paths. The remaining nineteen tests passed. This is a pre-implementation red and does not qualify the new behavior.

The preceding committed witness slice remains separately qualified: 2,069 tests, 43 suites, corpus, CLI, SDK and original five-app comparisons. The audit must not merge those results with the later failing work in progress.

## Independent spot checks

`GenericPackProbe.swift` emits a generic class with one ordinary type and a pack. Both compiler IR versions place A metadata at byte offset 88. The descriptor's immediate-member base is 80. The pack length occupies the first key word, and A occupies the next. `typeOfA` renders as `return ?`. In `identityA`, the raw instructions load A at +88, read its value witness table through −8 and tail-call `initializeWithCopy` through table slot +16. The published gate binary at commit `1fc51d3b39592c4dc13c09b840efba98cf618d99` (SHA-256 `bc7ad12bd26d3bc00e4a8fc3ad8d1602bfbf4c4048024cf1bbe3bb64f062a520`) incorrectly labels the witness B on the original Xcode 6.4.0 binary and on the command-line Swift 6.4.2 paired fixture. The paired fixture's ordinary `PlainBox.identityA` correctly labels its witness A. Artifacts in ignored `work/abi-gap-audit` include `GenericPackProbe.ll`, `GenericPackProbe.6.4.2.ll`, `g07-identityA-disassembly.txt`, `g07-identityA-baseline.txt` and `g07-paired-clt-baseline.txt`. [Probe source and commands](probes/README.md).

`AggregateBarrierProbe.swift` was compiled with the explicit 6.4.2 executable, SDK MacOSX27.0 and arm64 macOS 15 target at -O. Its `after` IR signature is `(i16, half, i16, i64)`: two integer pieces separated by an FP piece remain distinct. Swiftdc's integer-chunk set does not encode that distinction. The frozen rendered call currently declines both arguments; this probe establishes the schema mismatch without establishing a current wrong rendered value. The root plan must retain that evidence distinction.

`SuperInitializerProbe.m` reproduces a wrong semantic statement. The source initializer calls `consumeDescription([super description])` and then returns `[super init]`. Xcode Apple Clang 21.0.0 (clang-2100.3.34.2), -O2 ARC, arm64 macOS 15 with SDK27.0 emits distinct selectors and calls to the same objc_msgSendSuper2 stub. Independent LLVM disassembly records description at 0x948/call0x950 and init at 0x974/call0x97c. The qualified frozen witness release emits `self = [super description]`, incorrectly treating an ordinary super message as receiver initialization. Its subsequent `self = [super init]` is the actual initializer call. This is reproduced wrong output, not a speculative ABI gap. Artifacts are `SuperInitializerProbe.m`, `super-initializer-disassembly.txt`, and `super-initializer-structured.txt`.
