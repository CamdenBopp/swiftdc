## Compiler rules that constrain the implementation

- SIL first destructures eligible formal tuples according to the original abstraction pattern, with a distinct inout path. Result destructuring is distinct again. A source formal, a SIL formal, and an LLVM machine argument can have different cardinalities. Derive their mappings separately. [SILFunctionType.cpp, DestructureResults](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/SIL/IR/SILFunctionType.cpp#L1555-L1615), [DestructureInputs](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/SIL/IR/SILFunctionType.cpp#L2118-L2210).
- Native Swift lowering passes non-loadable types indirectly. Loadable TypeInfo contributes ordered, offset-bearing storage components to Clang SwiftAggLowering. Swift IRGen has separate parameter and result schema queries. The target implementation's ordinary budget is four **counted components**, with an integer wider than one word counted accordingly. Clang coalesces neighboring mergeable entries across its same-chunk test, preserving FP/vector barriers. A bag of sets keyed by eight-byte chunk loses this distinction. [GenCall.cpp, NativeConventionSchema](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenCall.cpp#L959-L986), [expand](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenCall.cpp#L1816-L1870), [Clang SwiftCallingConv.cpp](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/clang/lib/CodeGen/SwiftCallingConv.cpp#L429-L509), [Clang ABIInfo.cpp, occupiesMoreThan](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/clang/lib/CodeGen/ABIInfo.cpp#L240-L284).
- Struct/tuple TypeInfo visits each represented field at its fixed byte offset. Enum strategies differ: zero-/one-case singleton forwards its payload or contributes nothing, payload enum storage contributes its own typed payload and opaque excess tag entries. Single-payload extra inhabitants and common multi-payload spare bits have different semantics. Resilience requires a boundary/expansion context and proof of ABI-accessibility in addition to storage size. [GenStruct.cpp](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenStruct.cpp#L947-L975), [GenTuple.cpp](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenTuple.cpp#L276-L283), [GenEnum.cpp, strategies](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenEnum.cpp#L31-L91), [singleton](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenEnum.cpp#L535-L540), [payload expansion](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenEnum.cpp#L1548-L1565), [preferred payload schema](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenEnum.cpp#L1957-L1980).
- A nontrivial direct result disables sret for associated indirect results. Multiple indirect SIL results also disable it. Formal address results are a separate branch. A single truly sret buffer is x8 in LP64 Darwin. Ordinary leading buffers without sret consume the ordinary GP bank. A direct result can coexist with such a buffer. Parameter ordering must survive the result decision. [GenCall.cpp, addIndirectResult/expandResult/expandIndirectResults](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenCall.cpp#L677-L763), [expandDirectResult](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenCall.cpp#L1094-L1121), [Darwin PCS](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64CallingConvention.td#L359-L439).
- External signatures use Clang arrangement. Ordinary ObjC methods prefix self and _cmd, objc_direct omits _cmd, blocks prefix a block context. Clang C classifies HFA/HVA/coercion/indirect separately from Swift's flattening. The Darwin LLVM backend independently allocates GP/FP with natural-width fixed stack placements and selects a different assigner for unnamed varargs. Do not use generic AAPCS64 rules where Apple differs, or infer slots from LLVM type count alone. [GenCall.cpp, expandExternalSignatureTypes](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenCall.cpp#L1550-L1659), [Clang AArch64.cpp](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/clang/lib/CodeGen/Targets/AArch64.cpp#L364-L547), [Darwin varargs assigner](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64CallingConvention.td#L441-L462), [CCAssignFnForCall](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64ISelLowering.cpp#L7750-L7783).

## Order and oracle procedure

1. **P0, prevent false placements.** L02/L03 and source validation of L06 recursive direct claims. Initially decline contradictory shapes if exact component reconstruction is unavailable. Protect existing entry/call result safeguards and use validated cases to exercise the shared classifier.
2. **P0, shared schema.** L01/L04/L05/L07. Establish source slot, SIL formal, component, role, direction, byte interval, storage alignment, known layout and resilience. Separate value shape from placement state, from observed value identity, from source rendering. An opaque value may have proven placement and leave following formals identifiable.
3. **P1, implement target and foreign placement.** L08/L09/L10. Take one structured signature through entry seeding, ordinary/outgoing/indirect/tail values, summaries, use counts and both renderers. L11 follows exact fixed foreign placements. Role-dependent changes in L12 land with the responsible audits.
4. **Oracle per row.** Use separate caller and callee source inputs with noinline and distinguishable values; retain caller/trampoline in the linked image. Emit `swiftc -target arm64-apple-macosx27.2 -O -emit-silgen`, `-emit-ir` and `-emit-assembly` in separate runs, with analogous Onone runs and explicit module names. Use `clang -target arm64-apple-macosx27.2 -S -emit-llvm` and `-S` for C/ObjC. Verify actual linked bindings and disassemble the call and callee before comparing both renderers with independently executed scalar/native value checks. For cross-module coverage, build a separately compiled evolution-enabled module and its client. Use explicit executable paths and record SDK. Preserve optimization-driven specializations and tail calls instead of assuming the named fixture is the body being tested. Compiler fixtures already available as additional anchors include [select_enum.sil](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/test/IRGen/select_enum.sil#L77-L96) and [objc_structs.swift](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/test/IRGen/objc_structs.swift#L13-L53).
5. **Done for this slice.** Every admitted target/shape has parameter and result truth tables across entry, call, tail, projection and exits. Exact known location plus undefined or absent payload never becomes a value. Positive, adversarial and mutation tests prove each new rule, validate fixture presence, and cover missing/stripped/conflicting declarations. Any case without implementation or evidence is explicit in the matrix. This establishes the tested target and feature coverage only. arm64e, arm64_32, non-Darwin, uncommon Clang calling-convention attributes, and ABI differences across other compiler releases were not audited by this part.
