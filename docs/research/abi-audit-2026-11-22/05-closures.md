# Closure and function value ABI audit

Swift 6.4.2 source pin `83eb12448e4323abbf81b0153dced2faff02d22f`; LLVM pin `fb5f84d903a3b4e7aea15cd5666598a46f56c833`. Scope is ARM64 Darwin. Findings are source analysis and inspection of existing tests. This audit did not run new binaries, compiler or decompiler tests.

## C01 · Function value representation and entry convention

**Partial.** ExtInfo distinguishes AST Swift (thick), Block, Thin, CFunctionPointer and SIL-only Method, ObjCMethod, WitnessMethod, Closure, CXXMethod and four key-path accessors. GenFunc lowers native Thick, including noescape, to two words, Block to one block object pointer, and Thin/Method/WitnessMethod/Closure/CFunctionPointer/CXXMethod/key-path accessor to one pointer as values. ObjCMethod has a distinct lowered selector path. Closure means an unbound invocation function. Swift versus C calling language is independent of value width. [ExtInfo.h:308–424](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/include/swift/AST/ExtInfo.h#L308-L424) [GenFunc.cpp:605–665](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenFunc.cpp#L605-L665) [GenCall.cpp:381–404](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenCall.cpp#L381-L404) [GenCall.cpp:1578–1621](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenCall.cpp#L1578-L1621)

- SwiftLowering.swift:35–76,135–161 drops attributes in its balanced arrow check and treats recognizable function types as generally direct. Disassembler.swift:7549–7600,7788–7795 lacks general placement. TypeInference.swift:15–54 reads the rendered signature. ClosureCollectionCompilerOracleTests.swift:55–104 checks collection/closure returns but lacks the representation matrix.
- Use typed demangle representation and separate storage and entry records, feeding shared argument/result placement. Require the enclosing layout for nested aggregates and abstract parameters. Distinguish product function values in C09.

## C02 · Hidden context and receiver roles

**Partial.** Pointer-representable self may become swiftself while nonpointer self remains a formal. Thick closures also have swiftself. Synchronous throwing thin/closure entries may reserve a placeholder context. Async closure entry has separate async-context and swiftself roles, and throwing resume may use swiftself for error. ARM64 assigns swiftself to x20. [GenCall.cpp:1891–1918](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenCall.cpp#L1891-L1918) [GenCall.cpp:2020–2115](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenCall.cpp#L2020-L2115) [GenCall.cpp:2181–2199](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenCall.cpp#L2181-L2199) [GenCall.cpp:2328–2380](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenCall.cpp#L2328-L2380) [AArch64CallingConvention.td:68–75](https://github.com/swiftlang/llvm-project/blob/fb5f84d903a3b4e7aea15cd5666598a46f56c833/llvm/lib/Target/AArch64/AArch64CallingConvention.td#L68-L75)

- ValueTracking.swift:216–226,420–433,2456–2474 intentionally avoids treating arbitrary x20 as self. Disassembler.swift:6008–6105,9469–9576 proves particular receiver paths. ClosureCaptureTests.swift:9 demonstrates an unresolved forwarded capture.
- Add neutral context origin at proved entries, carry role provenance across aliases and spills, and identify the role independently at every call or continuation. Seed neither self nor captures from unrelated or stale x20; preserve distinct capture, receiver, placeholder and error roles.

## C03 · Partial apply and forwarded captures

**Partial.** The simple method path pairs the original function and self with no new thunk or heap box. Ordinary partial apply binds the formal suffix under substituted conventions. The context may adopt one object, be stack/heap allocated, and include necessary bindings, a dynamic function/context or witness. Optimal field layout does not promise source capture order. ObjC bound method applications dispatch inside the thunk. [IRGenSIL.cpp:4248–4427](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/IRGenSIL.cpp#L4248-L4427) [IRGenSIL.cpp:7684–7710](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/IRGenSIL.cpp#L7684-L7710) [GenFunc.cpp:2206–2250](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenFunc.cpp#L2206-L2250) [GenFunc.cpp:2302–2555](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenFunc.cpp#L2302-L2555) [SILGenFunction.cpp:576–628](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/SILGen/SILGenFunction.cpp#L576-L628)

- Disassembler.swift:9049–9066,10539–10608 and SwiftIdioms.swift:248 infer in-image local/register call inputs from body reads. Mixed banks lack ordering and context loads remain unresolved. ClosureCaptureTests.swift:9, ClosureCallRenderingTests.swift:19,100 and RegisterCallTests.swift:10 cover bounded cases.
- Derive partial-apply relations from verified pair provenance plus context creation, stores and forwarder dataflow. Handle direct adopted self and thin-to-thick null contexts. No capture identity from fixed offsets. Preserve machine-level reads and unknown fields after ambiguous joins.

## C04 · Blocks, C pointers and foreign references

**Conservative-decline for representation-specific invocation.** Swift block application uses the block object as an implicit foreign argument and dispatches through the invoke field. C pointer has no block argument. ObjC lowered methods carry selector information and use foreign receiver/argument conventions. Block layout optionally includes copy/dispose helpers. [GenCall.cpp:1578–1621](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenCall.cpp#L1578-L1621) [GenFunc.cpp:2756–2827](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenFunc.cpp#L2756-L2827) [IRGenSIL.cpp:4382–4406](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/IRGenSIL.cpp#L4382-L4406)

- Disassembler.swift:9049–9066 resolves known code addresses without proving block/C/Swift convention. ObjCArgumentABITests.swift covers selectors and RegisterCallTests.swift:10 arbitrary indirect extent. Neither proves the implicit block argument.
- Coordinate foreign ABI classification. Require a proved block object and invoke dereference or thunk contract. Support global/stack/copied blocks and authenticated pointer forms only as proved. Exclude the implicit object from source formals but preserve it in machine facts.

## C05 · Reabstraction and adaptation thunks

**Unverified.** SILGen builds independent source/destination contracts, translates parameters and results, and may bind an input function with DynamicSelf metadata or isolation. Reabstraction, sync-to-async, noescape conversions and actor isolation are entry-contract concerns. Rendered thunk prose alone cannot prove either set of lowered operands. - Give a thunk separate entry and forwarding operand plans. Verify both boundaries before collapsing wrappers. Include direct/indirect result changes and address creation/load, isolation and error/ownership effects.

## C06 · Closure propagation and capture ordering

**Supported for bounded free functions; source-risk for inferred capture semantics.** Optimizer removes propagated closure formals, appends unique root partial-apply captures in encounter order, and constructs a bare thin entry. The mangler stores c/E plus target and AST capture types, discarding SIL address/object category. A repeated closure points at an earlier argument and needs dependency validation. ## C07 · Dead and generic dropped operands, method specialization

**Partial and source-risk.** Signature mangler counts SIL arguments, including indirect results, and transforms can remove dead inputs, explode formals, change ownership or choose Thin. ## C09 · Autodiff and distributed entrypoints

**Unverified.** Differentiable values contain original/JVP/VJP, or original/transpose for linear. Each component has its own storage and invocation. Distributed calls can choose a thunk or bypass it locally under isolation conditions. Accessor/record/descriptor and method are distinct entities. ## C10 · Key-path getter/setter/equals/hash entry representations

**Unverified.** All four are native thin function values with dedicated signature expansion and a trailing buffer for serialized generic components. Their operand conventions differ by kind. The generic buffer cannot be treated as closure context, witness tail or a source formal. [ExtInfo.h:378–393](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/include/swift/AST/ExtInfo.h#L378-L393) [GenCall.cpp:1930–1974](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenCall.cpp#L1930-L1974) [GenCall.cpp:2140–2163](https://github.com/swiftlang/swift/blob/83eb12448e4323abbf81b0153dced2faff02d22f/lib/IRGen/GenCall.cpp#L2140-L2163)

- Add explicit per-entry kind and packet role shared with the metadata track. Keep serialized contents opaque unless the originating key-path record and proof of generic binding agree.

## Dependency-ordered changes

1. Introduce a typed proof for value representation, code identity, invocation convention and each hidden role. Keep separate completeness for each. Use common placement for entry, direct and indirect calls, results and type inference.
2. Implement measured native and foreign function-value representations with neutral context origins. Support proved function/context pairs and block identities through spill and join; permit physical summaries when a source mapping is unproved.
3. Replace scattered text fallbacks with ordered specialization transforms on lowered operands. Land Dead, ownership-only, generic drops and capture stacking before receiver changes. Enable async and generic binding only once descriptor, resume and generic metadata workstreams supply the requisite contracts.
4. Add proved forwarder/adaptor transfer first for simple native pairs, then reabstraction and async/foreign pairs. Validate key-path, autodiff and distributed special entries after ordinary calls share the same structured ABI model.

## Compiler and native validation

Resolve the absolute compiler and demangler from the same toolchain. Check actual `"$SWIFTC" -version`, hash and supplied build provenance. The closure collection oracle currently invokes `/usr/bin/xcrun … swiftc` at line 82, which can select the separately installed 6.4.0. Resolve the SDK with xcrun, and invoke the pinned compiler as `"$SWIFTC" -sdk "$SDK" -target arm64-apple-macos15.0`. Record target, SDK/build and compiler versions alongside artifacts.

Independently collect SILGen and SIL convention, substitutions and instruction; final LLVM IR and pre-LLVM-optimization IR when needed; arm64 assembly and runtime sentinel results. Use -Onone, -O, -Osize and separate-module resilient builds where relevant. A disappeared entry needs checked SIL or separate-module ABI preservation before claiming positive coverage. Hand-authored SIL is suitable for narrow rare representations when verified by the compiler and independently lowered into IR and assembly. Grammar-only tests for unsupported modifier shapes are separate from native claims.
